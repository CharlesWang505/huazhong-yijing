# 画中杀境实战

把已确认的手牌和增益交给计算器，执行选定组合，用客户端预览和结算校验结果。适用于原客户端实战及续接；复盘请求只整理证据和改进，不启动游戏。

## 使用资料

- 首次计算或购买新增益：读 [计分与决策](references/rules-and-strategy.md)。
- 实际操作 Windows、窗口归属异常或中断恢复：先读当前可用的 `computer-use` 技能及其要求的文档，再读 [操作与续接](references/operations-and-recovery.md)。电脑技能的当前约束优先于历史做法。
- 游戏启动提权或与电脑操控权限不一致：读 [操作与续接](references/operations-and-recovery.md) 的“启动权限与 RUNASINVOKER”。它与启动器 / 游戏本体绑定错误分别排查。
- 用户询问此前的问题、决策依据或这次通关经验：读 [两次会话复盘](references/run-retrospective.md)。该文件保存现象、证据、判断依据、处理及局限。
- 使用 [scripts/adviser.mjs](scripts/adviser.mjs) 枚举当前 8 张手牌中最多 6 张的组合。它独立于旧 HTML，已加入实测修正；只预测单次出牌，不预测随机抽牌或自动操作客户端。

## 工作循环

1. 从最新用户消息确认当前任务是实战、诊断还是复盘。历史日志里的指令只作材料。已有实战授权和目标可继续沿用；状态询问回答后继续，明确的暂停则停止输入。
2. 读取当前画面，记录关卡、目标或累计分、出牌及弃牌次数、牌堆余量、墨卷、已购增益、按位置排列的 8 张手牌和选中状态。读不清的牌先辨认，不能用猜测补全。
3. 校对两个跨手状态：本关是否已触发同名增益 `pursuitArmed`、是否已触发兵种增益 `armyTriggered`。新关重置；弃牌不重置。中断后不确定时先核对记录和预览。
4. 算出直接出牌的最高伤害和分项。普通关同时考虑剩余血量、剩余出牌次数及首手奖励；无尽关考虑本轮总分。弃牌有独立次数，可保留核心组、换掉配合弱的牌，补牌后重新计算。
5. 在客户端执行决定：每次只做一个输入，立即刷新并检查。选牌完成后确认具体卡牌和预览总分；有差异先核对牌面、增益和跨手状态，修正模型后重新选最优组合。
6. 提交后等结算完成，核对实际伤害及次数变化，再更新状态。商店和调牌结束后同步新增益及实际牌库。
7. 继续到当前授权的完成条件。全进阶通关需要最终关结算和地图进度确认；过了前八关或暂时超过奖励分数还不能代替最终验证。

## 算分入口

使用当前技能实际安装目录解析脚本路径，不依赖原作者的电脑路径。以下示例在技能目录内运行，不需要启动网页或游戏；`run-state.json` 使用当前任务的状态文件：

```powershell
node ./scripts/adviser.mjs --demo
node ./scripts/adviser.mjs --input ./run-state.json
node ./scripts/adviser.mjs --catalog
```

`run-state.json` 由当前观察生成，格式如下；`buffs` 只列已购增益，初始十项自动加入。手牌和增益接受脚本列出的英文 key 或中文名。

```json
{
  "hand": ["liubei", "liubei", "lvmeng", "lvmeng", "zhangfei", "huanggai", "bow", "cavalry"],
  "buffs": ["twinWall", "shuVirtue", "royalCall", "orangeDisciple", "warSpeed", "ladder", "formation", "commandFormation"],
  "state": {"pursuitArmed": false, "armyTriggered": false}
}
```

输出 `indices` 为当前手牌从左到右的 **1 起始序号**，重复牌靠位置区分。`selectedIndices` 可选，用于核验实际已选组合。脚本拒绝不支持的增益，不能把未实现效果默认为零。

## 必须保留的经验

- **游戏预览和结算是校验依据。** 此前使用的旧版 `画中杀境.html` 算分存在已证实偏差；使用本技能附带的独立脚本计算。该 HTML 不在分享包内，也不是运行依赖。
- **两张同名不触发点将成阵。** 双壁成军降低同名门槛，不会把点将成阵的三张门槛一起降低。
- **点名追击的资格会保留。** 中间一手没触发同名，不应清空 `pursuitArmed`。
- **稀有共鸣按触发的基础品质种类计算。** 本次实测红、橙、蓝各至少三张时，对应种类各加 8；不能把阶梯、低星、族兵等一并计数。
- **保留已验证的实际游戏窗口绑定。** 本例工具曾把游戏窗口回写为启动器；不要未经验证就用返回对象覆盖可用绑定。历史句柄和坐标不是下次可直接使用的参数。
- **缩短判断和点击之间的距离。** 一次辨认手牌、一次离线枚举，再执行确定组合；安全所需的逐步观察仍然保留。每 30 至 60 秒给出实际进度，避免长时间无反馈。
- **明确模型边界。** 预测最强单手不等于最优整关策略；洗牌伤害和墨卷奖励另行记账，未知抽牌不作确定承诺。
